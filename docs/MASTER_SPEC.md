# MASTER_SPEC — Шаховий тренер для Android

Єдине джерело вимог для всіх агентів. Якщо інші документи або чати суперечать цьому файлу, діє цей файл. Зміни вносить лише Архітектор після погодження з власником проєкту.

## 1. Мета

Безкоштовний застосунок з відкритим кодом для Android, який навчає шахів від нульового рівня до сильного клубного гравця (орієнтир 2200+ Elo). 2200+ є метою розвитку гравця, а не гарантованим результатом курсу.

## 2. Обмеження (обов'язкові)

- Нуль додаткових фінансових витрат на розробку й підтримку. Разова плата за акаунт Google Play (приблизно 25 $) є єдиним винятком.
- Код відкритий, ліцензія **GPL-3.0-or-later** (GPL версії 3 або, на вибір отримувача, будь-якої пізнішої). Stockfish ліцензовано під GPLv3-or-later (за записом Шахового ядра, `docs/THIRD_PARTY.md`, SW-001).
- Без платних API, платних серверів і платних голосів.
- ШІ не викликається всередині застосунку. Пояснення будуються на аналізі Stockfish та шаблонах або готуються заздалегідь як файли.
- Усі зовнішні ресурси (шрифти, фігури, звуки, бази задач) перевіряються на сумісність ліцензії й записуються в `docs/THIRD_PARTY.md`.
- Монетизація (реклама або інший дохід) допускається. Підключення до інтернету потрібне лише для неї. Вибір рішення й перевірка його ліцензії відносно GPL-3.0-or-later виконуються до реалізації (див. розділ 13).

## 3. Мови й тексти

Перший реліз: українська (uk) та англійська (en).

- **Тексти інтерфейсу** (кнопки, меню, повідомлення, назви тем задач і рівнів складності, шаблони пояснень) лише через `strings.xml`: `values/` для en, `values-uk/` для uk. Жодних рядків для користувача в коді.
- **Тексти уроків і довгі навчальні пояснення** зберігаються як дані в `content/<мова>/` (`content/uk/`, `content/en/`), а не в `strings.xml`. Формат задає `docs/CONTRACTS.md`.
- Кожен текст уроку має бути в **обох** мовах. Відсутність перекладу є помилкою збірки (перевірка в CI).
- Мовно-незалежні дані (задачі, дебютні дерева, позиції) зберігаються в `content/common/` і посилаються на тексти через ключі.
- Модулі `core-chess` і `learning` не містять текстів для користувача: лише ключі й параметри.
- **Ліцензія власних текстів уроків і пояснень: GPL-3.0-or-later** (як і код). Сторонній контент зберігає свою ліцензію й обліковується в `docs/THIRD_PARTY.md`.

## 5. Етапи

1. **Архітектура й прототип:** ця специфікація, структура модулів, дизайн-система, критерії готовності.
2. **MVP, офлайн:** дошка, легальні ходи, гра проти Stockfish з рівнями складності, збереження партій, базові задачі.
3. **Навчання:** курс за рівнями, задачі, повторення, дебюти, ендшпілі, розбір партій.
4. **Полірування:** анімації, озвучення, переклади, оптимізація, тести.
5. **Публікація:** Google Play (F-Droid лише якщо в збірці немає пропрієтарних рекламних SDK).

Онлайн-гра поза межами першого релізу. Якщо буде потрібна пізніше, розглядаються лише безкоштовні варіанти (Lichess API з його лімітами або peer-to-peer).

## 6. Функції MVP

- Дошка з легальними ходами, шахом, матом, патом, рокіровкою, взяттям на проході, перетворенням пішака.
- Гра проти Stockfish з вибором складності.
- Аналіз позиції, оцінка переваги.
- Імпорт і експорт PGN, завантаження з FEN.
- Збереження партій і прогресу локально.
- Тактичні задачі (бази з відкритою ліцензією, наприклад CC0).
- Світла й темна теми. Сучасний дизайн у дусі Lichess: чиста, швидка, читабельна дошка, акцент на грі та навчанні, без зайвих елементів, плавні анімації ходів, кілька тем дошки й наборів фігур. Орієнтуємося на стиль і зручність, але не копіюємо брендинг, логотипи й оригінальні матеріали Lichess. Кожен набір фігур і звуків перевіряється на ліцензію окремо (docs/THIRD_PARTY.md).
- Гра проти Stockfish, задачі, уроки й аналіз працюють без інтернету. MVP не використовує й не запитує інтернет. Після MVP інтернет може знадобитися лише для монетизації, якщо її оберуть (розділ 13.2). Онлайн-гра з суперником у першому релізі відсутня.

## 7. Навчальна система

- Діагностика початкового рівня.
- Рівні: початківець, любитель, клубний гравець, сильний гравець. Критерії переходу задає Методист.
- Теми: правила, тактика, стратегія, дебюти, ендшпілі.
- Підказки трьома кроками: натяк, напрямок, конкретний хід.
- Інтервальне повторення помилок.
- Розбір партій: критичні моменти, класифікація помилок, пояснення людською мовою, що спираються на варіанти рушія, а не на здогадки.

## 8. Ролі агентів

| Роль | Відповідає за | Не робить |
|---|---|---|
| Архітектор | Специфікація, модулі, контракти, інтеграція, стандарти | Не змінює перевірену шахову логіку без тестів |
| Шахове ядро | Правила, інтеграція Stockfish, аналіз, FEN/PGN/UCI | Не чіпає UI та контент |
| Android і UI | Екрани, навігація, теми, локальне збереження, доступність | Не змінює API шахового ядра |
| Навчання і контент | Програма, задачі, уроки, коментарі, переклади uk/en | Не пише код ядра |
| QA | Тест-кейси, регресія, звіти про дефекти | Не виправляє код самостійно, лише повідомляє |

Один агент не змінює модулі іншого. Потрібна зміна чужого модуля оформлюється запитом у `project_log.md`.

## 9. Структура репозиторію

```
docs/                    специфікація, журнал, CONTRACTS.md, THIRD_PARTY.md
app/                     Android-застосунок (UI, Room, реалізація портів learning)      → :app
core-chess/
  api/                   чистий Kotlin: модель, правила, PGN, інтерфейси рушія       → :core-chess:api
  engine-android/        NDK/JNI-обгортка Stockfish, вихідний код Stockfish           → :core-chess:engine-android
learning/                чистий Kotlin: навчальна логіка й адаптація                  → :learning
content/
  common/                мовно-незалежні дані: задачі, дебюти, позиції
  uk/                    тексти уроків і пояснень українською
  en/                    тексти уроків і пояснень англійською
tests/
  contract/              контрактні тести для всіх реалізацій інтерфейсів
```

- Відповідальність: `core-chess/*` належить Шаховому ядру, `app/` належить Android і UI, `learning/` і `content/` належать Навчанню і контенту (код `learning` пишеться за контрактами Архітектора), `tests/contract/` веде QA разом з власниками інтерфейсів.
- Залежності лише в один бік: `app → learning → core-chess:api`; `app → core-chess:engine-android → core-chess:api`. `content/` не містить коду.

## 10. Правила взаємодії

- Контракти між модулями (інтерфейси, формати даних) фіксуються в `docs/CONTRACTS.md` і не змінюються без запису в журналі. Кожен контракт має позначку «MVP» або «Пізніше».
- Версія контрактів: до v1.0 допускаються несумісні зміни, але кожна з записом у журналі. Після v1.0 сумісне доповнення це MINOR, несумісна зміна це MAJOR.
- Іменування:
  - Kotlin за офіційним стилем.
  - Пакети коду: `org.chesstrainer.<модуль>` (`org.chesstrainer.app`, `org.chesstrainer.core`, `org.chesstrainer.engine`, `org.chesstrainer.learning`). Це **робочий простір імен коду**, він не змінюється під час вибору остаточної назви.
  - `applicationId` для Google Play задається лише в одному місці: змінна `appId` у `app/build.gradle.kts`. **Тимчасове значення `org.chesstrainer.app`**; остаточне визначається до етапу 5 (розділ 13.2) і після публікації не змінюється. Відладкова збірка має суфікс `.debug`. `namespace` модулів (`org.chesstrainer.app`, `org.chesstrainer.engine`) від `applicationId` не залежить і при зміні назви не змінюється.
  - Робоча назва застосунку: «Шаховий тренер» / «Chess Trainer» (рядок `app_name`). Остаточна назва не блокує розробку.
  - Ключі рядків: `snake_case` з префіксом екрана або домену (`game_`, `puzzle_`, `puzzle_theme_<id>`, `difficulty_<id>`).
- Гілки: `feature/<модуль>` (`feature/core-chess-api`, `feature/engine-android`, `feature/app`, `feature/learning`, `feature/content`), у `main` через перевірку.
- Кожна зміна шахової логіки супроводжується окремими тестами.
- Кожен власний файл коду й контенту має SPDX-заголовок `GPL-3.0-or-later`:
  - Kotlin, C++ (власна JNI-обгортка), Gradle Kotlin DSL: перші рядки файлу
    ```
    // SPDX-License-Identifier: GPL-3.0-or-later
    // SPDX-FileCopyrightText: 2026 Chess Trainer contributors
    ```
  - XML (`strings.xml`, ресурси) і Markdown (`content/<мова>/`): `<!-- SPDX-License-Identifier: GPL-3.0-or-later -->`.
  - Файли без коментарів (JSON у `content/common/`): заголовок не ставиться; ліцензія задається для всієї теки окремим файлом-декларацією (формат на кшталт REUSE визначає Архітектор, якщо знадобиться перевірка в CI).
  - Вихідні файли Stockfish і інших сторонніх компонентів зберігають **власні** заголовки; їх не змінюють.
  - Власника авторських прав у рядку `SPDX-FileCopyrightText` може уточнити власник проєкту (ім'я чи «contributors»).
- Кожен текст уроку додається одночасно в `content/uk/` і `content/en/`.
- Після кожного етапу: збірка, всі тести, оновлення `project_log.md`.
- Заборонено довільно перейменовувати класи, змінювати формат даних чи переписувати чужі модулі.

## 11. Критерії готовності MVP

- Усі правила шахів проходять тести (включно з крайовими випадками: рокіровка, взяття на проході, перетворення, пат, повторення позиції, правило 50 і 75 ходів, недостатній матеріал).
- Perft-тести (`docs/CONTRACTS.md`, розділ 7) проходять у CI (GitHub Actions): швидкий набір на кожен pull request і push у `main`, глибокий набір щодоби. Злиття в `main` при червоному CI заборонене.
- Контрактні тести (`tests/contract/`) проходять для всіх реалізацій інтерфейсів, зокрема для обраної реалізації `EngineService`.
- Нативна збірка Stockfish для всіх ABI зі списку (розділ 4) проходить у CI.
- Гра проти Stockfish стабільна щонайменше на двох фізичних пристроях `arm64-v8a` з різними версіями Android (одна з них якомога ближча до API 26) і на кількох розмірах екрана (телефон і великий екран або емулятор).
- Слабкі рівні для початківців (`Strength.Handicap`) пройшли тести легальності й монотонності сили.
- Падіння або зупинка рушія не призводить до втрати поточної партії: після перезапуску партію можна продовжити. Стан `EngineState.Failed` і повторний `start()` перевіряються тестом аварійного завершення рушія. Для збоїв рівня процесу це вимагає режиму окремого процесу; режим обирається після прототипу (`docs/CONTRACTS.md`, 3.4).
- Рушій не зависає непомітно: зависання транспорту чи запуску за встановлений таймаут перетворюється на стан помилки з можливістю перезапуску (`docs/CONTRACTS.md` 3.4); прогін ≥ 200 циклів запуску й аналізу без жодного незавершеного виклику.
- Байткод APK не викликає API Android, новіших за `minSdk 26`, крім явно перелічених недосяжних винятків (статична перевірка в CI, `docs/CONTRACTS.md` 7.2); поведінку на Android 8 підтверджено на фізичному пристрої.
- Усі видимі тексти доступні в uk та en.
- Основні функції працюють без інтернету. MVP не запитує дозвіл `INTERNET`.
- Усі зовнішні ресурси мають перевірену ліцензію (`docs/THIRD_PARTY.md`, статус «Перевірено» або «Власний»), зокрема Stockfish, файл нейромережі, бібліотека правил.

## 12. Публікація в Google Play

- Акаунт розробника, верифікація.
- Політика конфіденційності з описом даних, які збирає рекламний сервіс (якщо він є).
- Заповнити розділ «Безпека даних» (Data safety) у Play Console відповідно до реально використаних SDK.
- Для користувачів з ЄС та Великої Британії потрібна згода на персоналізовану рекламу (через сертифіковану платформу керування згодою, наприклад, інструмент самої рекламної мережі).
- Актуальні вимоги до тестування нових акаунтів перевірити в Play Console перед запуском.
- Сторінка застосунку: опис, скриншоти, іконка, мови uk/en.
- Вказати відкритий код і ліцензію GPL-3.0-or-later.

## 13. Рішення й відкриті питання

### 13.1 Ухвалені рішення (власник, 2026-10-28)

| Питання | Рішення |
|---|---|
| Мінімальна версія Android | API 26 (Android 8.0) |
| Цільовий вік | 13+ (підлітки й дорослі). Застосунок не позиціонується як дитячий і не бере участі в програмі для сімей. Мінімізація даних: без акаунтів, без аналітики, усі дані локально |
| Монетизація в MVP | Немає. Лише порожній інтерфейс `Monetization`. Без дозволу `INTERNET` у MVP |
| Інтеграція Stockfish | Нативна бібліотека через NDK/JNI |

### 13.2 Відкриті питання

- **Остаточна назва й `applicationId`** (до етапу 5). Зараз тимчасово `org.chesstrainer.app`. Перевірити унікальність у Google Play, F-Droid, GitHub, базах торговельних марок. `applicationId` після публікації не змінюється.
- **Байткод Java 11 на Android 8–10** (chesslib): виконання на API 26–29 не перевірено (`docs/CONTRACTS.md`, розділ 8, пункт 11).
- **Рідна купа рушія:** ≈ 100 МБ невідомого походження понад мережу й Hash (`docs/CONTRACTS.md` 8, п. 16); дослідити до етапу 4.
- **Мережа NNUE без копії** (етап 4): для MVP копія 98,5 МБ у пам'ять пристрою. Кандидат на заміну: передача мережі з нестиснутого asset через іменований канал (FIFO; +16 МБ APK, без копії, `start()` ≈ 0,5–0,6 с проти 0,42 с). До рішення перевірити: роботу в процесі `:engine`, на Android 8 і пристроях інших виробників, розмір завантаження з Google Play. Ліміти розміру Google Play перевірити до етапу 5.
- **Другий пристрій для критеріїв MVP** (розділ 11): `arm64-v8a`, якомога ближче до API 26, бажано без dotprod.
- **Джерела навчального контенту:** перевірка ліцензій кандидатів у `docs/THIRD_PARTY.md`.
- **Модель монетизації після MVP:** пожертви, реклама або одноразова підтримка. Якщо обрано пропрієтарний SDK: юридична перевірка сумісності з GPL-3.0-or-later до реалізації (це не юридична консультація).
- **Вимоги Google Play** (перевірити в Play Console перед етапом 5): анкета цільової аудиторії й вікового рейтингу для 13+, статус розробника, вимоги до тестування нових акаунтів, актуальний `targetSdk`.
