## Запити між агентами

Формат: `[від кого] → [кому]: що потрібно, чому, до коли`

- [Архітектор] → [Шахове ядро]: перевірити chesslib (ліцензія, підтримка, perft, повторення, 50/75 ходів) і дати висновок «беремо / власна реалізація». Від цього залежить реалізація `ChessRules`. До кінця етапу 1.
- [Архітектор] → [Шахове ядро]: прототип Stockfish як нативної бібліотеки через NDK/JNI на `arm64-v8a`: запуск, `bestMove`, `analyse`, скасування, відновлення після падіння; виміряти розмір APK з NNUE. До кінця етапу 1.
- [Архітектор] → [Шахове ядро]: **слабкі рівні для початківців** (`Strength.Handicap`, CONTRACTS 3.5): мінімум 3 рівні нижче мінімального UCI_Elo; мінімум читати з опцій рушія, не хардкодити (значення за пам'яттю близько 1320, перевірити); описати алгоритм ослаблення в `docs/`; детермінованість через `Random`; тести легальності й монотонності сили. Плюс таблиця `DifficultyPresets` з id рівнів. Алгоритм і кількість рівнів до кінця етапу 1, реалізація на етапі 2.
- [Архітектор] → [Шахове ядро, Android і UI]: підтвердити або оскаржити сигнатури [MVP] у CONTRACTS.md (розділи 2, 3, 5) до початку етапу 2.
- [Архітектор] → [Android і UI]: каркас Gradle-модулів (`:app`, `:core-chess:api`, `:core-chess:engine-android`, `:learning`), `minSdk 26`, пакети `org.chesstrainer.*`, `applicationId` в одному місці конфігурації, без дозволу `INTERNET`; пропозиція UI для `DrawClaimable`; вибір інструмента збору ліцензій (SW-006).
- [Архітектор] → [Навчання і контент]: схема й скрипт перевірки бази задач (CONTRACTS 6.1); оцінка обсягу вибірки й розміру; перевірка ліцензії CT-001; початковий список `ThemeId`.
- [Архітектор] → [QA]: план контрактних тестів (`tests/contract/`) і perft-набір; тест-кейси на слабкі рівні.
