## Дефекти тестового скрипта (виправлено)

### D-01. Скрипт не бачив жодного рядка logcat
- Збірка: `ad0d24e`, `tests/run-device.ps1`, SM-S928B, Android 17.
- Що робила: `run-device.ps1`; кожен сценарій завершувався `finished=False (timeout)`, файли `device-<сценарій>-<режим>.log` порожні, загалом понад годину.
- Очікувано: рядки `RESULT`/`END` з тегу `EnginePrototype`.
- Фактично: фільтр `logcat -s EnginePrototype:I EnginePrototype:W EnginePrototype:E` залишав лише рівень `E`, бо для одного тега діє останній рівень у списку (перевірено: той самий запуск `hello` дав порожній вивід із цим фільтром і повний з `-s EnginePrototype`). Сценарії на пристрої при цьому виконувалися.
- Серйозність: Висока для процесу (прогін марний), на продукт не впливає.
- Відтворюється: так (2 з 2).
- Кому: QA. Стан: виправлено в `6b67352` (`-s EnginePrototype:I`).

### D-02. `connectedDebugAndroidTest` видаляє застосунок
- Фактично: після завдання застосунок відсутній, `am start` дає `Error type 3 ... PrototypeActivity does not exist` (дані власника).
- Серйозність: Висока для процесу. Стан: виправлено в `ad0d24e` (повторний `installDebug` і перевірка `pm list packages --user 0`; без застосунку скрипт виходить з кодом 4).

### D-03. `adb shell` без `--user` на телефоні з кількома профілями (0, 95, 150)
- Фактично (дані власника): `pm list packages` інколи звертається до профілю 150 («Shell does not have permission to access user 150»).
- Стан: виправлено в `ad0d24e` (`--user 0` в `am start`, `am force-stop`, `pm list`). Також скрипт чекав повний таймаут після невдалого `am start` і вживав режим `inprocess`, якого немає (код знає `inproc`/`remote`); виправлено там же, додано `-DryRun`.

## Блокери процесу (не дефекти продукту)

### B-01. Телефон SM-S928B зник із USB посеред сесії (стан: знято в сесії 2, телефон підключено)
- **Що робила:** на початку сесії `adb devices` показував `RZCX326349A device`, `adb shell getprop` повернув модель `SM-S928B`, версію Android `17`. Після кількох прогонів Gradle (`./gradlew test` та інші) запустила `./gradlew :app:connectedDebugAndroidTest`.
- **Очікувано:** тести запускаються на пристрої.
- **Фактично:** `DeviceException: No connected devices!`; `adb devices -l` порожній; `adb kill-server`, `adb start-server` не допомогли; у Windows `Get-PnpDevice -PresentOnly` не показує ні Samsung, ні Android-пристрою (лише «USB Composite Device» і кореневі хаби). Лог: `tests/results/connected-android-test.log`.
- **Серйозність:** блокує всі пристроєві перевірки (`PLAN.md` розд. 4, `MANUAL.md`).
- **Відтворюється:** не застосовно (подія стороннього середовища). Причину (кабель, режим USB, живлення, блокування екрана, налагодження вимкнулося) QA не встановила. **Потрібна дія власника:** підключити телефон, розблокувати, підтвердити відладку; потім `powershell -File tests/run-device.ps1`.
